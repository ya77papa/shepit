# Шепіт без інтернету (mesh) — концепція

Статус: **етапи 1–2 реалізовано з версії 0.2.27, етапи 3–4 (естафета й шлюз) — з 0.2.31** (експериментально).

### Що зроблено в етапах 1–2

- Mesh-конверт, щоденні теги пари, шифрування без серверного сертифіката (`core/src/crypto/mesh.rs`).
- Обмін між двома телефонами HELLO/OFFER/WANT/ENV/ACK (`mesh/MeshLink.kt`).
- Локальна Wi-Fi мережа: пошук mDNS (`_shepit._tcp`), обмін по TCP.
- Телефон-телефон: пошук Bluetooth LE, обмін через **L2CAP-канал поверх BLE** (Android 10+),
  а не Wi-Fi Direct — він не вимагає підтвердження з'єднання на іншому телефоні. Wi-Fi Direct
  можна додати пізніше для великих файлів.
- Немає інтернету й mesh увімкнено → повідомлення стає в чергу (годинник кольору акценту),
  після підтвердження отримувача — дві галочки. Інтернет повернувся — дочекане йде ще й через
  сервер; дублікати отримувач відкидає за id повідомлення.

### Що зроблено в етапах 3–4

- Протокол обміну v2 (сумісний з v1): HELLO з випадковим nonce, в OFFER — ознаки «я твій контакт»
  `HMAC(секрет пари, "shepit-mesh-hello|" ‖ nonce співрозмовника)[:8]` для кожного свого контакту.
  Співрозмовник упізнає, що ми знайомі, але сторонній не дізнається, хто є хто.
- Налаштування «Передавати чужі повідомлення»: лише від контактів (типово) / від усіх / ні.
  Чужі конверти — окрема таблиця `mesh_relay`, до 20 МБ і до 7 днів; пропонуються всім, кого
  зустрінемо (естафета). Підтвердження (ACK) — лише від адресата: тоді носій забуває копію.
- Шлюз: сервер має статичний ключ P-256 (`data/gateway.key`, створюється сам, у git не потрапляє),
  публічна частина — `GET /v0/gateway-key`. Відправник кладе в конверт `gw` =
  ефемерний ключ ‖ IV ‖ AES-256-GCM(`{to: скринька, tag, exp, body}`), ключ AES =
  SHA-256("shepit-gateway-v1" ‖ ECDH ‖ ефемерний ключ). Носій з інтернетом шле
  `POST /v0/gateway` (підписано його зареєстрованим акаунтом), сервер розкриває пакет і кладе
  конверт у скриньку адресата з `wake = "mesh"`; застосунок адресата розшифровує його як mesh.
- Вікно впізнавання тегів — тиждень назад і день уперед (конверт міг довго їхати).
- Черговість підключень: підключається телефон з меншим nonce (Wi-Fi — меншим ім'ям служби),
  інший чекає; якщо вхідного немає понад хвилину — підключаємось самі.
- Фото теж ідуть естафетою (у межах 20 МБ сховища) — так простіше для людей; ліміт сховища
  не дає забити телефон.

### Свідомо відкладено

- Шифрування самого каналу між телефонами (Noise): у етапах 1–2 по каналу йдуть лише вже
  зашифровані конверти з тегами; сусід у тій самій Wi-Fi може бачити теги й розміри.
  Ознаки контактів і пакет шлюзу цього не погіршують: перші щоразу інші, другий — шифротекст.
- Ліміт «N конвертів на годину з одного джерела» й поширення підтверджень доставки («вакцина»)
  — поки носій забуває копію лише, коли сам зустріне адресата, вивантажить у шлюз або мине 7 днів.
- Перший контакт без інтернету (QR з пакетом ключів).

## Навіщо

Сценарії (у порядку важливості):

1. **Укриття, відключення світла.** Люди в одному будинку чи підвалі, мобільний зв'язок ліг.
   Повідомлення мають ходити всередині й виходити назовні з тим, хто вийде туди, де є зв'язок.
2. **Одна Wi-Fi мережа без провайдера.** Роутер працює (на батареї, від станції), інтернету немає:
   дім, офіс, пункт незламності.
3. **Місто без зв'язку (естафета).** Великий район довго без зв'язку — повідомлення йдуть через
   телефони людей, що проходять повз.

Дзвінків без інтернету не обіцяємо (хіба в межах однієї Wi-Fi мережі — пізніше).

## Головна ідея

Шифрування вже відбувається на телефоні, сервер лише переносить зашифровані конверти.
Без інтернету конверт може перенести інший телефон — прочитати його він не зможе.
Кожен телефон тримає невелике сховище чужих конвертів і обмінюється ним із тими, кого зустріне.
Щойно хтось отримає інтернет, він вивантажує конверти на сервер (і забирає зустрічні).

## Транспорти

| Етап | Транспорт | Для чого | Дальність |
|---|---|---|---|
| 1 | Локальна Wi-Fi мережа (пошук через mDNS/NSD, обмін по TCP) | укриття з роутером, офіс, пункт незламності | уся мережа |
| 2 | Bluetooth LE — пошук; Wi-Fi Direct — обмін | телефон-телефон без роутера | ~30–100 м |
| 3 | Естафета (той самий обмін, але чужі конверти несемо далі) | місто без зв'язку | без меж, повільно |
| 4 | Шлюз: телефон з інтернетом вивантажує/забирає конверти на сервері | зв'язок «назовні» | — |

Сервіси Google (Nearby Connections) не використовуємо — Шепіт працює без них. Беремо системні
Android API напряму.

## Конверт для mesh

```
MeshEnvelope {
  tag:     16 байт  — «кому» на сьогодні (див. нижче)
  expires: час      — після нього ніхто не несе (типово 7 днів)
  body:    шифротекст Signal-сесії (як зараз, лише без серверного сертифіката)
  gateway: необов'язково — копія для сервера, зашифрована ключем сервера
}
id = SHA-256(конверт) — щоб не приймати один конверт двічі
```

### Хто кому пише — без постійних адрес

Зараз на сервер іде адреса скриньки отримувача — постійна. У mesh її бачили б усі телефони на
шляху, і можна було б відстежувати, хто кому пише. Тому:

- для кожної пари контактів обидва телефони виводять спільний секрет зі своїх ключів (DH);
- `tag = HMAC(секрет, дата ‖ напрям)` — змінюється щодня й різний «туди» і «назад»;
- отримувач заздалегідь рахує теги всіх своїх контактів на сьогодні й учора й одразу впізнає
  «це мені, від Аліси»; для решти це випадкові байти.

Тег одночасно відповідає на питання «від кого»: його можуть порахувати лише двоє.

### Відправник без сервера

Зараз «запечатаний відправник» спирається на сертифікат, який видає сервер на 4 години —
без інтернету він спливе. У mesh-конверті він не потрібен: відправника підтверджує тег (його знає
лише пара) і сама Signal-сесія.

### Шлюз на сервер

Сервер не зможе розібрати тег (він не знає секретів пар). Тому відправник одразу додає
`gateway` — адресу скриньки й конверт, зашифровані **публічним ключем сервера**. Телефони на
шляху бачать лише шифротекст; сервер розшифровує, кладе в скриньку як звичайну пошту, а
застосунок отримувача обробляє її тим самим шляхом, що й mesh.

### Перший контакт

Без сервера чужих ключів не отримати. Додати нову людину офлайн — лише особисто: QR-код
міститиме ключі (пакет PreKey). З уже доданими контактами mesh працює одразу.

## Хто що несе

Налаштування «Передавати чужі повідомлення»:

- **Лише від моїх контактів** (типово): мій телефон бере конверти тільки в тих, кого я знаю
  (підтверджено рукостисканням), і несе їх далі куди завгодно.
- **Від усіх користувачів Шепоту**: швидша естафета, але й більше навантаження.
- **Вимкнено**: лише мої власні повідомлення.

Обмеження, щоб mesh не забивався сміттям:

- сховище чужих конвертів — до 20 МБ (налаштовується), найстаріші видаляються першими;
- з одного джерела — не більше N конвертів на годину;
- фото в естафету не йдуть — лише напряму (етапи 1–2);
- «вакцина»: коли отримувач отримав конверт, підтвердження доставки поширюється тим самим
  шляхом, і всі, хто його побачить, видаляють свою копію.

## Рукостискання між телефонами

Канал між двома телефонами шифрується (Noise). У режимі «лише контакти» сторони показують
одна одній свої ключі (щоб упізнати контакт). У режимі «від усіх» — тимчасові ключі, без
постійної особи: інакше будь-хто міг би сканувати навколо й бачити, хто з користувачів Шепоту поруч.

## Батарея

- Режим **«Mesh увімкнено»** вмикає людина (і вимикає), коли зв'язку немає; можливо — автоматично,
  якщо сервер недоступний довше N хвилин.
- У межах однієї Wi-Fi мережі — практично безкоштовно.
- Bluetooth-пошук — у фоні з паузами; Wi-Fi Direct — лише на час обміну.
- Частина виробників (Xiaomi, Samsung, Huawei) агресивно вбиває фонову роботу — знадобиться
  інструкція «дозволити Шепоту працювати у фоні» для кожного.

## Інтерфейс

- У шапці списку бесід: «Немає інтернету · mesh: поруч 3 телефони».
- Біля повідомлення: «надіслано через mesh», а коли дійде — звичайні галочки.
- Налаштування → «Без інтернету»: увімкнути mesh, що передавати, обсяг сховища.

## Тестування

Bluetooth і Wi-Fi Direct працюють лише на справжніх телефонах — потрібні щонайменше три
Android-пристрої (є). Логіку (теги, конверти, синхронізація, «вакцина», ліміти) перевіряємо
автоматичними тестами без телефонів; транспорт — на телефонах за сценаріями:

1. Два телефони в одній Wi-Fi без інтернету.
2. Два телефони без Wi-Fi поруч (Bluetooth + Wi-Fi Direct).
3. А → Б → В: А і В ніколи не бачать одне одного, Б ходить між ними.
4. Б із «шлюзом»: А без зв'язку, Б виходить туди, де є інтернет.

## Етапи

1. **Протокол і локальна Wi-Fi мережа.** Mesh-конверт, теги, рукостискання, обмін між телефонами
   в одній мережі. Уже корисно для укриттів з роутером і пунктів незламності.
2. **Телефон-телефон** без роутера: Bluetooth LE + Wi-Fi Direct.
3. **Естафета** з налаштуванням «що передавати», лімітами й «вакциною».
4. **Шлюз** на сервер.
