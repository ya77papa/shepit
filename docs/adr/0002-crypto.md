# ADR-0002: Криптографія

- Статус: **Прийнято для 1:1**, групи — на обговоренні
- Дата: 2026-11-15

## Рішення

### Чати 1:1 — libsignal `libsignal-protocol` v0.108.0
- Початок сесії: **PQXDH** (X25519 + ML-KEM/Kyber1024) — постквантовий захист від
  «збери зараз, розшифруй потім» уже з першого дня.
- Далі: Double Ratchet (+ постквантовий ратчет SPQR, який іде в залежностях libsignal).
- Підключення з git за тегом; збірка потребує лише `protoc`.
- Уся робота з libsignal — лише в `core/src/crypto/`. Решта коду бачить `Account`
  і формати з `core/src/wire.rs`.
- Сервер збирається **без** криптографії (`shepit-core` без фічі `crypto`).

### Ідентичність
- Окремий ключ Ed25519 з прототипу прибрано: ключ ідентичності = ключ libsignal
  (33 байти). Один ключ — одна «адреса» людини.
- Довіра при першому контакті (TOFU); зміна ключа співрозмовника блокує надсилання.

## Виміряно в прототипі
| | Розмір шифротексту libsignal | Розмір payload у конверті (JSON+hex) |
|---|---|---|
| Перше повідомлення (PreKey, з Kyber) | ~1,8 КБ | ~3,7 КБ |
| Відповідь | ~90 Б | ~270 Б |
| Наступні | ~105 Б | ~400 Б |

Висновки:
- Поки співрозмовник не відповів, **кожне** повідомлення — PreKey (~1,8 КБ). Для mesh через BLE
  це суттєво → врахувати на етапі 3.
- JSON+hex подвоює розмір → бінарний формат у ADR-0003 обов'язковий.
