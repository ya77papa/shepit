# Шепіт (Shepit)

Месенджер із наскрізним шифруванням: без номера телефону, з мінімумом метаданих.

## Що вміє

- Особисті бесіди й групи (до ~100 учасників): текст, голосові, фото, реакції, відповіді з цитатою.
- Шифрування Signal Protocol (libsignal) і «запечатаний відправник»: сервер не знає, хто кому пише.
- Фото й голосові — лише транзитом: сервер видаляє їх одразу після доставки, недоставлені — за 3 дні.
- Голосові дзвінки (WebRTC), через власний ретранслятор.
- Канали: зашифровані (за посиланням) і публічні.
- «Доставлено» / «переглянуто», «в мережі» — з вимикачами приватності.
- Блокування застосунку PIN-кодом і відбитком, зашифрована резервна копія.
- Без інтернету (експериментально): повідомлення контактам через телефони поруч —
  спільна Wi-Fi мережа без провайдера або Bluetooth (docs/mesh-concept.md).
- Працює без сервісів Google; застосунок оновлюється сам (підписані релізи на GitHub).
- Адмінпанель сервера: режими реєстрації, запрошення, користувачі, канали.

## Структура

```
core/      Ядро на Rust: криптографія, протокол, формат повідомлень, локальне сховище
server/    Сервер доставки (Rust), Dockerfile і docker-compose
clients/   Клієнти: android/ + android-core/ (Rust через UniFFI);
           web/ — сторінка завантаження, адмінпанель і тестовий клієнт (не публікується);
           web-core/ (WASM для тестового клієнта), cli/
docs/      Архітектура, рішення (ADR), план
```

## Спробувати

Android: **https://shepit.razom.isroot.in** → «Завантажити APK»
(або [GitHub Releases](https://github.com/ya77papa/shepit/releases/latest)). Застосунок оновлюється сам.

Поки що лише Android 8.0+. Веб-версії чату немає: код, що завантажується з сервера щоразу,
дозволив би тому, хто захопить сервер, підмінити клієнт і забрати ключі (ADR-0011).

## Принципи

1. Не вигадуємо власну криптографію — тільки перевірені бібліотеки.
2. Сервер — «тупий листоноша»: не знає, хто з ким спілкується.
3. Формат зашифрованих конвертів не прив'язаний до сервера як до транспорту.
4. Образи збирає CI (GitHub Actions); на сервері — лише готові Docker-образи з лімітами пам'яті.
5. Відкритий код: кожен може перевірити, що ми не читаємо повідомлень.
